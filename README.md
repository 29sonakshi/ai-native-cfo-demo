# Meridian AI Cockpit

A **Databricks App** demo that shows how a CFO's finance team can explore governed
data in plain English with **Databricks AI/BI Genie** — and govern their AI spend
alongside their financials. Built around a fictional digital‑banking group,
**Meridian Bank**, and its recently‑acquired subsidiaries.

> **Demo / synthetic data.** Meridian Bank and all figures in this project are
> fictional and generated by the setup notebooks. Nothing here is real financial data.

## What it demonstrates

- **Genie as the hero.** A natural‑language Q&A tab (and a launchpad into **Genie One**)
  answers finance *and* AI‑cost questions over governed Unity Catalog tables — the
  same assistant, the whole business, grounded in real queries with visible SQL.
- **AI spend as a CFO metric.** AI/LLM cost is tied to revenue and budget the way a
  CFO thinks about it — spend vs. budget, spend as a % of revenue, model‑provider
  mix, and single‑provider concentration risk.
- **A finance cockpit** — group P&L, revenue bridge, ARR/margin trends, and
  per‑entity performance in one pane of glass.

## The app (3 tabs)

| Tab | What it shows |
|-----|---------------|
| **Group Perf** | Group KPIs, revenue bridge waterfall, ARR/margin trends, geographic breakdown, and a Claude‑generated executive synthesis grounded in the real numbers. |
| **AI Spend** | AI infrastructure cost by entity, provider, team, and model; budget utilization; Frontier vs. Open‑weight tier mix; and provider‑concentration risk. |
| **CFO Q&A** | Natural‑language questions answered by a **Databricks Genie** space over the Unity Catalog tables, plus an **Open in Genie One** launchpad for the full assistant experience (draft a board‑ready document, etc.). |

## Architecture

```
FastAPI (app.py)
  ├─ /api/kpis, /api/trends, /api/entities, /api/cash, ... → server/data_routes.py     → SQL Warehouse
  ├─ /api/ai/overview, /api/ai/providers, /api/ai/teams   → server/ai_routes.py       → SQL Warehouse
  ├─ /api/genie/ask                                       → server/genie_routes.py    → Genie Space API
  ├─ /api/synthesis                                       → server/synthesis_routes.py → Foundation Model
  └─ /* (SPA catch‑all)                                   → frontend/dist/            → React build
```

React + Vite + TypeScript frontend (`frontend/src/`), FastAPI backend (`server/`),
Unity Catalog gold tables as the data layer, a Genie space for NL Q&A, and a
Foundation Model endpoint for the AI synthesis.

## Prerequisites

- A Databricks workspace with **Unity Catalog** enabled
- A **Serverless (or Pro) SQL Warehouse**
- A **Foundation Model** serving endpoint (default: `databricks-claude-sonnet-4-6`)
- **Databricks CLI** configured (`databricks auth login`)
- **Node.js 18+** and **Python 3.11+** for building/running locally

## Setup

### 1. Clone

```bash
git clone https://github.com/29sonakshi/meridian-ai-cockpit.git
cd meridian-ai-cockpit
```

### 2. Create the sample data

Import `setup/01_generate_sample_data.py` into your workspace as a notebook, set the
**catalog** / **schema** widgets (defaults: `meridian_demo` / `meridian_cfo` /
`meridian_ai`), and **Run All**. It creates 8 Unity Catalog tables:

- `<catalog>.meridian_cfo`: `dim_entity`, `fact_financials_monthly`, `fact_cash_monthly`, `fact_revenue_bridge_monthly`
- `<catalog>.meridian_ai`: `fact_ai_spend_monthly`, `fact_ai_spend_by_provider`, `fact_ai_spend_by_team`, `fact_ai_spend_detail`

### 3. Create the Genie space

Import `setup/02_create_genie_space.py` as a notebook, set the **catalog** and
**warehouse_id** widgets, and **Run All**. Note the **Space ID** it prints.

### 4. Configure

For a **deployed Databricks App**, edit `app.yaml` and set `WAREHOUSE_ID`,
`GENIE_SPACE_ID`, and `UC_CATALOG` (leave `UC_SCHEMA` / `UC_SCHEMA_AI` unless you
changed the widgets).

For **local development**, copy `.env.example` → `.env` and fill in the same values
(auth uses your Databricks CLI profile — no tokens are stored in the repo).

### 5. Build the frontend

```bash
cd frontend
cp .env.example .env      # set VITE_GENIE_ONE_URL to https://<your-workspace-host>/one
npm install
npm run build             # outputs frontend/dist/, served by FastAPI
cd ..
```

> The compiled UI (`frontend/dist/`) is **not** committed — you build it here. The
> `VITE_GENIE_ONE_URL` you set is baked into the build, so the **Open in Genie One**
> button points to your own workspace (the button is hidden if it's unset).

### 6. Run or deploy

**Local:**

```bash
pip install -r requirements.txt
set -a && source .env && set +a
uvicorn app:app --reload --port 8000
# open http://localhost:8000
```

**Deploy as a Databricks App:**

```bash
databricks apps create meridian-ai-cockpit
databricks sync . /Workspace/Users/<you>/meridian-ai-cockpit
databricks apps deploy meridian-ai-cockpit \
  --source-code-path /Workspace/Users/<you>/meridian-ai-cockpit
```

After deploy, grant the app's service principal `SELECT` on both schemas, `CAN_USE`
on the SQL warehouse, and `CAN_RUN` on the Genie space.
